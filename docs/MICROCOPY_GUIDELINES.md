# Microcopy Guidelines

## Tone
**Confident, crypto-native, not corporate**

Keep the "plain English" promise front-and-center in all user-facing copy.

## Examples

### Empty State
```
No scans yet. Paste a contract and let AI hunt the red flags.
```

### Loading State
```
Analyzing code… checking liquidity… hunting honeypots 👀
```

### Safe Result
```
✅ All clear. No honeypot patterns found. Liquidity looks healthy.
```

### Risky Result
```
⚠️ Rug-pull likely. 2 functions can drain funds. Read why →
```

### Error Messages
```
That doesn't look like a valid address on this chain. Choose the right chain and try again.
```

## Principles

1. **Plain English First**: Avoid technical jargon when possible. If technical terms are necessary, explain them simply.
2. **Crypto-Native**: Use language that resonates with crypto traders and DeFi users.
3. **Confident**: Be direct and clear about what we found and what it means.
4. **Not Corporate**: Avoid formal, corporate-speak. Be conversational and authentic.
5. **Action-Oriented**: Tell users what to do next, not just what happened.

## When Writing Copy

- Use emojis sparingly but effectively (✅ ⚠️ 👀)
- Use contractions (don't, can't, we'll) for a conversational tone
- Be specific with numbers and details ("2 functions can drain funds" not "multiple issues found")
- Use active voice ("AI hunts red flags" not "red flags are detected")
- Include clear CTAs when needed ("Read why →", "Try again")
